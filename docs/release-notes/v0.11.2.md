本版本修掉两处「点了不是想要的结果」的日常体验问题：Windows 托盘左键单击会直接开始截图，以及 Linux 贴图开启穿透后被下层窗口盖住。

## 修复（Windows 托盘左键）

- **左键单击托盘图标不再直接开始截图**：此前 Windows 上单击托盘图标本想打开菜单，却立刻进了截图覆盖层（用户主诉「点一下图标就开始截图了」）。原因是 Win/mac 的托盘代码把左键单击/双击派发成快速截图，同时 Windows 侧又显式关掉了「左键弹菜单」把这个手势让给它；v0.6.1 只为 macOS 修过这个叠加，Windows 一直保留旧设计。现在三平台语义统一：**左键与右键单击都只弹出菜单**，截图走菜单里的「截图」项或默认 F1 热键。Linux 本来就是单击弹菜单，行为不变。

## 修复（Linux 贴图）

- **贴图开启穿透后不再被下层窗口盖住**（用户主诉「点穿透就后台了」）：根因其实不是穿透——`with_always_on_top` 建窗选项在部分窗口管理器（Deepin kwin 实测）不落地，贴图从未真正持有「置顶」状态，只靠「最后激活的窗口」假性压在最上层；穿透后点击落到下层窗口会激活它，贴图就被盖住。现在建窗后会补发置顶状态（贴图窗口无输入事件时不重绘，同步主动重绘）。自 v0.9 起就存在，只是穿透场景才暴露：新建贴图立刻就有置顶属性，激活其他窗口后堆叠不变。
- **贴图穿透改为「区域穿透」**（用户主诉「开启即整窗穿透，按钮再也点不到，只能 Esc 或去托盘」）：开启后只有图片区域点击穿到下层窗口，工具条那一条窄带（穿透按钮/缩放/关闭等）仍可正常操作，**再点一次穿透按钮即恢复**；穿透中改变窗口大小（条带按钮本身仍可点，缩放会改尺寸）时会重算并重发保留区。Win/mac 的系统级原语只有「整窗穿透」一种粒度，做区域方案需要一个额外的子窗口或消息子类化，收益不成比例，那里保持原行为与文案不变。
- 顺手重绘了穿透按钮图标（此前的「窗口轮廓 + 横穿箭头」辨识度差）：改为圆盾 + 斜射穿盾的箭。

## 已知事项

- 上述 Linux 截图/贴图修复均在 Deepin 25 X11 真机点验（xprop 可查到 `_NET_WM_STATE_ABOVE`、穿透区分别用指针探测实测）；托盘左键的修正在本机只做到交叉编译验证（Windows GNU 目标），Windows 真机手感请按 `docs/VERIFY.md` 的 Windows 人工项复验一次。
- 既是行为变更也值得一并说明：习惯了「左键快速截图」的用户请改用 F1（默认热键）或在配置面板里给截图绑一个组合键。

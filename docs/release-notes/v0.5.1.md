修复 Windows 包在干净系统上无法运行的问题。功能与 v0.5.0 相同，Windows 用户请直接用本版本。

## 修复

**Windows 缺 VCRUNTIME140.dll 打不开**

v0.5.0 的 Windows 包（`*-setup.exe` 与 `*.zip`）在没装 Visual C++ 运行库的机器上双击无反应或报缺少 `VCRUNTIME140.dll`。原因是 MSVC 目标默认**动态**链接 C 运行时，产物依赖系统里的 VC++ 运行库——这违反了项目「无动态库依赖、拷走即用」的硬约束。开发和打包机器通常装过运行库，所以此前一直没暴露。

修复：新增 `.cargo/config.toml`，Windows 目标开启 `+crt-static`，把运行时静态链接进 exe。openh264（MP4 编码的 C++ 源）不会与之冲突——`cc` 会跟随 `crt-static` 自动把 `/MD` 换成 `/MT`。

代价是 exe 体积略增，仍在 20MB 预算内；换来的是下载即能跑。

## 其他

- `scripts/package.sh` 新增打包期依赖校验：扫描 Windows 产物的导入表，发现 VCRUNTIME / MSVCP / libstdc++ 等外部运行时 DLL 直接让打包失败。这类缺陷在打包机上测不出来，只能在出包环节拦住，不能等用户装完才发现
- 主程序与安装器都纳入校验（安装器是用户双击的第一个 exe，它缺 DLL 连安装都进行不了）
- `tray::window_icon` 补 Linux cfg 门控，消除 Windows/macOS 构建的 dead_code 警告

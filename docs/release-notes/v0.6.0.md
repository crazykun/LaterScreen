本版本没有新功能，全部是「装不上、打不开」这类拦在功能之前的问题：Windows 静态链接 CRT、启动失败不再静默、打包产物不再混入不能分发的构建。功能与 v0.5.0 相同。

v0.5.1 已撤回（其 tag 与 release 一并删除），修复内容全部包含在本版，Windows 用户直接用 v0.6.0。

## 修复

**Windows 缺 VCRUNTIME140.dll 打不开**（原 v0.5.1）

v0.5.0 的 Windows 包在没装 Visual C++ 运行库的机器上双击无反应或报缺少 `VCRUNTIME140.dll`。MSVC 目标默认**动态**链接 C 运行时，产物依赖系统里的 VC++ 运行库，违反项目「无动态库依赖、拷走即用」的硬约束。开发机与打包机通常装过运行库，所以此前一直没暴露。

修复：`.cargo/config.toml` 给 Windows 目标开 `+crt-static`，运行时静态链进 exe。openh264（MP4 编码的 C++ 源）不冲突——`cc` 会跟随 `crt-static` 自动把 `/MD` 换成 `/MT`。代价是体积略增，仍在 20MB 预算内。

**启动失败不再静默**

改 GUI 子系统后（v0.5.0 为了消除 cmd 黑框），Windows 下的 stderr 没有接收方：启动期 panic——字体解析、窗口或 GL 上下文创建失败——是彻底无声的死亡，双击后什么都不发生，用户和维护者都拿不到任何线索。

修复：进程启动即 `AttachConsole(ATTACH_PARENT_PROCESS)` 探测有无父控制台，从终端起时 `--help` / `qr` / `ocr` 的输出与报错照常可见；双击起时没有控制台，致命错误改用 `MessageBoxW` 弹窗上报。同时装 panic hook——`panic = "abort"` 下 hook 仍会先跑，这是唯一能让启动期 panic 留下信息的位置。

**OpenGL 不可用时给出可自救的指引**

原先只抛 eframe 的原始错误，用户看到一串 glutin 术语无从下手。现在把 `eframe::Error::{OpenGL, NoGlutinConfigs, Glutin}` 翻译成分条建议：Windows 侧列显卡驱动（Windows 更新给的版本常缺 OpenGL）、虚拟机开 3D 加速、以及放一份 `opengl32sw.dll` 做软件渲染兜底；Linux 侧列 mesa 安装与 `LIBGL_ALWAYS_SOFTWARE=1`。

**打包：不能分发的产物不再混入 dist**

两个只在打包环节暴露、但直接坑到用户的问题：

- `x86_64-pc-windows-gnu` 只是「本地没有 Windows 时的编译替身」，产物带 `libstdc++-6.dll` 外部依赖（openh264 的 C++ 侧，mingw 下压不掉）。它与发布用的 MSVC 包同名，实测有人拿它装到干净虚拟机上报缺 DLL。现在文件名强制加 `-localtest` 后缀——构建输出里的警告会被淹掉，`dist/` 下的文件名不会。
- Windows runner 的 git bash 没有 `zip`，走的是 `7z` 分支，而 `7z a out "$stage"/*` 会把 `dist/.stage/<name>/` 整条路径写进归档：v0.5.1 的 zip 解压出来是四层空目录套一个 exe。改为先 `cd` 进 stage 再打包。

## 其他

- `scripts/package.sh` 新增打包期依赖校验：扫描 Windows 产物导入表，发现 VCRUNTIME / MSVCP / libstdc++ 等外部运行时 DLL 就让打包失败。主程序与安装器都纳入（安装器是用户双击的第一个 exe，它缺 DLL 连安装都进行不了）。这类缺陷在打包机上永远测不出来，只能在出包环节拦住
- 校验用 `grep -a` 扫字符串而非 `objdump`——本函数要在 Windows runner 的 git bash 里跑，那里没有 binutils；`-a` 必须带，否则 grep 把 exe 当二进制文件跳过、静默返回「没找到」
- `tray::window_icon` 补 Linux cfg 门控，消除 Windows/macOS 构建的 dead_code 警告
- 历史面板：热键在面板已置于后台时能唤到前台（300ms 心跳轮询 + `Minimized(false)` / `Visible` / `Focus`）

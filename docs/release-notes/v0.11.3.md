本版本修掉配置面板的一批「看得见但读不清」的问题，并新增手动更新检测。

## 新功能：检查更新

- 配置面板底部新增「检查更新」：查 GitHub 上的最新 release tag，有新版本时页面顶部出现提示条（「有新版本 vX.Y.Z」+「去下载」），点它直接用默认浏览器打开下载页。
- **手动触发，不后台自动联网**：常驻托盘不会在启动或周期轮询里外连，只有你点了按钮才发一次请求。联网用的是纯 Rust 的 rustls，不引入任何动态库依赖（产物 13.5MB → 14MB，距 20MB 上限仍有 5MB 余量）。
- 查不到结果（没网、GitHub 不可达、响应异常）会明确显示「未能确认：…」，**不会**报成「已是最新」——那种说法会骗过真正有更新待装的用户。

## 修复：配置面板配色可读性

- **选中文字不再看不见**（此前选中底色是红的、选中的字也是红的，等于红底红字）：选中态现在按主题配对底色与文字色——浅色是淡红底配深红字、深色是暗红底配浅粉字，对比度都在 7:1 以上。这个改动同时作用于输入框里的文本选区、下拉列表的当前项、滑块轨道和输入框聚焦框。
- **品牌红作文字/描边时按主题调深浅**：品牌红本身亮度居中，当文字用在浅色界面上只有 3.85:1、深色 4.35:1，都低于可读线（4.5:1）。现在文字用深一档的红（浅色）或亮一档的红（深色），描边比文字再推一档；承载白字的实心按钮底色也压深一档（原来的红配白字差 0.27 到线）。
- **提示条（Toast）跟随主题**：此前保存成功之类的提示恒为半透明黑底白字配红框，浅色主题下就是在白面板上糊一块黑。现在浅色是白底深色字、深色是深灰底浅色字，描边与投影都跟随主题；历史面板里的提示同步改掉。

## 修复：热键重复不再静默失效

- 同一个组合绑到两个动作时（比如截图和取色都是 F1），此前只有一个会触发，另一个静默失效，界面上看不出任何异常——热键事件的匹配键由「修饰键+主键」直接算出，同组合的 id 完全相同，事件只会命中先注册的那个。
- 现在保存时会拦下并告诉你是哪两个动作撞了；录入时也即时提示并保留在录制态，不会把冲突的值写进去。顺带把「可绑热键的动作」收敛成一处定义（注册、菜单文案、面板校验与行序共用），以后新增动作不会再漏掉某处。

## 已知事项

- 配色与热键修复均在 Deepin 25（X11）真机点验；对比度改为单元测试锁住（选中文字、聚焦框描边、品牌红前景与白字填充各自有门槛），浅色 Toast 的底色对比度受白底上限约束，靠描边与投影区分层次而非压暗面板。
- 「检查更新」的「有新版本」分支靠本地改版本号构造验证（未为此发真 tag）；真机验证步骤见 `docs/VERIFY.md`。

本版本全部是 macOS 平台问题，主题是「把 macOS 从能编译修到能用」：托盘交互、Dock 图标、历史面板位置，以及最严重的——录屏/滚动截图选区后全部消失。Linux/Windows 行为不变（除非注明）。

## 修复

**macOS：录屏 / 滚动截图选完区后一切消失**

现象：菜单里点「录屏」或「滚动截图」，框选区域松手后覆盖层关闭，但状态窗口再也不出现，什么都没发生。

根因是进程模型撞上了 macOS 的窗口系统限制：这两个功能此前在**同一个进程**里先后跑两个 eframe 窗口——先框选覆盖层、再录制状态窗，各自要跑一轮事件循环。Linux（X11）和 Windows 允许同进程反复跑事件循环，所以一直没暴露；macOS 的 winit 底层是 NSApplication，事件循环**每进程只能启动一轮**，第二个窗口的事件循环直接拉不起来，静默失败。

修复：框选覆盖层用完自己的事件循环额度后，带显式 `--region` 重启自身转交新进程执行后续工作（状态窗/录制/拼接），保证每进程恰好一个事件循环——与托盘「动作全部 spawn 独立子进程」是同一个模式。录制格式、时长、帧率、质量、输出路径等参数经 argv 原样转发，语义不变。滚动截图的标注预览窗同理：拼接完成后 PNG 经 stdin 交给独立的 `annotate` 子进程（隐藏子命令，不出现在 `--help`），不再在拼接进程里开第二个窗口。

**macOS：点托盘图标同时弹菜单又开截图**

tray-icon 的「左键弹菜单」（`menu_on_left_click`）默认开启，而事件处理器又把左键单击派发成快速截图——结果是菜单弹出来的同一瞬间截图覆盖层也开了，用户体感就是「一点图标就开始截图」。现在 macOS 左键只弹菜单（系统惯例），右键同。Windows 保持原设计：左键快速截图、右键弹菜单（显式关掉左键弹菜单，消除两者叠加）。

**macOS：Dock 里常驻一个点了没反应的图标**

托盘进程的事件循环默认以 Regular 形态启动 NSApplication——macOS 会给「一个应用」应有的待遇：Dock 图标。而这个进程的全部 UI 都在菜单栏，Dock 图标点了自然没有窗口可开。修复：托盘进程改用 Accessory（菜单栏应用）形态，不再占用 Dock。各功能窗口（截图覆盖层/配置/历史/贴图）都是独立子进程、各自的形态，不受影响。

**macOS：历史面板从右下角移到右上角**

原先贴主屏右下角是按 Deepin 的 dock 位置设计的；macOS 的状态栏在顶部，右下角看起来像随机出现。现在 macOS 上贴主屏右上、菜单栏下方（兼容标准 24pt 与刘海屏 37pt 菜单栏）。Linux 仍贴右下角。

## 其他

- 历史面板与滚动截图预览的窗口摆放改为相对主屏原点计算，多屏（副屏在主屏上方/左侧）不再错位

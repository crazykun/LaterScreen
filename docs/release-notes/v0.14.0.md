本版主题是**本地中文 OCR 落地 + 设置面板重构**：新增可下载的 PP-OCRv4 中文识别引擎（不依赖 Python / Ollama / GPU / 系统 tesseract），设置面板改微信式左侧分类导航，界面强调色由品牌红换成与截图选区同源的 LaterScreen 蓝。

## 🔎 本地中文 OCR（PP-OCRv4 mobile，可选下载）

- **纯 Rust 本地识别**：新增 PP-OCRv4 mobile 检测 + 识别模型（tract-onnx 推理，CPU 即可），中文 + 英文。不需要 Python、常驻模型服务、GPU 或系统 tesseract；识别全程在本机完成，截图不上传。Linux 真机实测 960×180 中英文图约 1.0s。
- **按需下载，不捆绑**：约 15.6MB 模型在设置面板里显式下载（检测模型 + 识别模型 + 字典），固定来源、固定大小与 SHA-256 校验、HTTPS（ureq+rustls）、原子落地，校验通过才生效。缓存优先绝对路径 `XDG_CACHE_HOME/lscreen/ppocr/v1/`，否则 `~/.cache/lscreen/ppocr/v1/`。
- **优先级**：有效显式环境变量 `LSCREEN_OCR_ENGINE` > 配置 `[ocr].engine` > 已下载的 PP-OCR > 系统 OCR（Win/mac）/ tesseract（Linux）> 内置 ocrs。**默认 auto 不会偷偷下载模型**；已安装则自动优先。
- **失败不静默降级**：显式选择 PP-OCR 后模型缺失/损坏只报错并引导修复，不回退到 ocrs 输出拉丁乱码；设置面板提供「检查 / 下载 / 校验」三个入口，跑完都有明确结论提示。
- **体积预算 20MB → 30MB**：为本地 OCR 引擎让出余量，单独提交说明用途与增量。**不可妥协的仍是「单文件 + 无动态库依赖」**，体积数字只是它的代理指标；新增依赖前仍须评估链接影响。
- 来源与许可见 [OCR_MODELS.md](docs/OCR_MODELS.md)，真机验证步骤见 [VERIFY.md](docs/VERIFY.md)。

## ⚙️ 设置面板改分类导航

- **微信式左侧导航**：原单页长卡片滚动改为左侧固定 148px 分类栏 + 右侧内容区，按功能域归组为「通用 / 截图 / 录屏 / 文字识别 / 热键 / 关于」六页，每页短而聚焦；窗口加宽到 720×560。
- **交互打磨**：滚轮翻页（内容可滚动时自动让位给滚动）、保存按钮未修改时置灰/有修改时高亮、关闭按钮在脏状态下变「取消」、放弃修改确认框主题化、输入框/下拉/数字框统一 32px 等高、目录支持文件夹选择器、文件名模板带帮助提示与示例预览。

## 🎨 品牌色改为 LaterScreen 蓝

- **强调色 #e53935 → #2196f3**：原来红强调色与红色选区边框在同一套界面里互相打架（用户反馈「配色太丑了」），统一为与截图覆盖层选区同源的蓝色。默认标注色同步跟随，Windows 安装器界面一并换色。
- **对比度全部重配并单测锁住**：蓝色比红色更亮，作前景在浅色侧只有 2.85:1（当年红色是 3.85:1），所以 `accent_ink` / `accent_line` / `ACCENT_FILL` 三个主题化替身一个都不能省；selection 仍是「底色 + 文字色成对配」，浅色 #bbdefb + #0d47a1、深色 #14406b + #9ecbff。
- **品牌色只有一处定义**：`theme::ACCENT`、`theme::ACCENT_HEX`、`core::Rgba::RED`、`config.default_color` 由新增断言钉死同值，杜绝「UI 是蓝的、画出来是红的」。
- 录屏画面内的点击涟漪与录制边框**刻意保留红色**——那是落进成品画面的瞬时提示，跟界面强调色走会像水印。

## 🛠️ 修复

- 输入框文字曾被自绘底色整个盖住（表现为「文件名模板空白」「目录选完不回显」，值其实已写入）；输入框内边距与下拉框统一到同一令牌，不再显得贴左。
- 修 `Negative child size` 崩溃：Grid 单元格内的 `available_width()` 在测量阶段拿到极小值，减去按钮预留后为负；改从卡片级推导稳定宽度并钳底。
- 配置面板改为单例并支持唤起：此前连开两次会堆叠两个窗口，各自写 config.toml 互相覆盖。

本版本修复「Ctrl+C 复制退出从未生效」的隐藏缺陷（egui-winit 劫持组合键所致，影响所有历史版本），并按用户反馈微调截图工具栏：关闭按钮挪到复制按钮旁、图标尺寸统一、复制按钮悬停反馈加强。

## 修复：Ctrl+C 复制退出从未生效（影响所有历史版本）

- **根因在 egui-winit 而非本应用**：egui-winit 0.35 的键盘事件入口会无条件把 Ctrl+C/X/V 识别为剪贴板意图，转译成 egui 的 `Event::Copy/Cut/Paste` 后直接返回——原始的 `Key::C` 按键事件根本不会进入事件列表。应用侧的 `consume_key(Ctrl, C)` 自迁移到 egui 0.35 起就是永远匹配不上的死代码，表现为按 Ctrl+C 毫无反应（复制、退出都没发生）。真机对照实验确认：Ctrl+S 保存、Enter 交付、Esc 退出都正常，唯独 Ctrl+C 连剪贴板都没写——修饰键喂送无恙，缺失的正是 C 键事件本身。
- **截图覆盖层**：复制退出改听 `Event::Copy`（保留原按键匹配作兜底），并加门控——文本框聚焦时（如编辑标注文字、二维码输入）Ctrl+C 仍让位给正常的文本复制，不会误触整个截图退出；画布文字编辑另有独立的模态保护。
- **贴图窗口**：同款修复。贴图窗 Ctrl+C 复制后按设计常驻不关窗（右键或托盘菜单关闭），此前按了毫无反应。
- **排查提示**：若升级后 Ctrl+C 仍无效，请确认按下的对象是截图覆盖层/贴图窗口本身（需要窗口持有键盘焦点；在终端或其他应用里按 Ctrl+C 依旧属于对应程序自身的复制）。

## 变更：截图工具栏收尾布局与悬停反馈

- **关闭（退出）按钮挪到最右侧、紧贴绿色复制按钮**，组成一对「出口」语义（直接退出 vs 复制并退出），与左侧的交付动作（保存/上传/贴图/识别/生成）视觉分组；原先关闭按钮单列在交付组队首，与主操作隔了整排图标。
- **关闭与复制按钮尺寸从 32×32 收成与其他图标一致的 24×24**：v0.11.5 把复制按钮放大一圈以补足去掉文字后的视觉权重，用户反馈反而突兀——绿色实心底本身就是最强的视觉锚点。
- **复制按钮悬停反馈加强**：悬停压深从 8% 提到 20%（`#2e7d32` → 白字对比度 5.13 → 7.17，仍超 AA 的 4.5 一截），按钮缩小到 24×24 后原先的压深幅度肉眼不可辨（用户反馈 hover 无区别）。方向仍是压深而非提亮：绿底提亮会让白色对号对比度跌破达标线。悬停倍数的安全区间由 theme 对比度回归测试锁住。

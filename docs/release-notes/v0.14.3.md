本版主题是**修复 macOS Apple Silicon（M 系芯片）上截图等全部图形界面进程启动即崩溃**：v0.11.8–v0.14.2 在 Apple Silicon mac 上无法使用任何图形界面功能（托盘点「截图」约 0.3 秒即崩、生成崩溃报告），本版恢复可用。Intel mac 不受影响。

## 🛠 修复

- **Apple Silicon 上 GUI 子进程首帧必崩**：`set_dock_icon`（v0.11.8 引入的 Dock 图标补设）把 `objc_msgSend` 声明成了 C 变参形状（`...`）。Apple arm64 的变参调用约定会把匿名实参压到**栈**上，而 `objc_msgSend` 是汇编实现的定参函数、只从 `x2/x3/…` 寄存器读实参——`+[NSString stringWithUTF8String:]` 拿到寄存器残留垃圾做 `strlen`，直接 SIGSEGV。x86_64 的变参实参仍走寄存器，因此当年 Intel 真机验证通过、Apple Silicon 上从 v0.11.8 起所有 eframe 子进程（截图覆盖层、取色、贴图、历史面板、设置面板、录制交互与状态窗）首帧必崩。修复为按定参形状声明（0 参 / 1 参两个声明，`clashing_extern_declarations` 警告显式放行并注明缘由）；全仓扫描确认无其他变参 extern 与原生 `msg_send`。
- 真机（M6 / macOS 27）验证：修复后 GUI 子进程存活无崩溃、`lscreen shot` 截屏 2560×1440 真实像素、OCR（Vision 引擎）对确定性文字图精确识别、二维码识别路径正常、`cargo test --workspace` 全绿。

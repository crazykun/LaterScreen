本版主题是**修复 macOS Apple Silicon（M 系芯片）上截图等全部图形界面进程启动即崩溃**，以及**修复屏幕录制授权后仍反复弹窗、截图黑屏**；同时产物改用自签名证书密封签名，TCC 授权身份跨版本稳定——**此后升级不再需要重新授权**。原 v0.14.3 曾以该版本号短暂发布（约一天）后撤并，全部内容并入本版。

## 🛠 修复

- **Apple Silicon 上 GUI 子进程首帧必崩**（v0.11.8–v0.14.2）：托盘「截图 / 取色 / 贴图 / 历史 / 设置 / 录制交互」在 M 系芯片上点开约 0.3 秒即崩。根因是 `set_dock_icon`（Dock 图标补设）把 `objc_msgSend` 声明成 C 变参形状——Apple arm64 的变参调用约定把匿名实参压到栈上，而 `objc_msgSend` 是汇编定参函数、只从 `x2/x3/…` 寄存器读实参，`+[NSString stringWithUTF8String:]` 对寄存器残留垃圾做 `strlen` 直接 SIGSEGV。x86_64 变参实参仍走寄存器，故当年 Intel 真机验证通过、arm64 漏网两个多月。修复为按定参形状声明（0 参 / 1 参两个声明，`clashing_extern_declarations` 显式放行并注明缘由）；全仓扫描确认无其他变参 extern 与原生 `msg_send`。
- **授权后仍反复弹「屏幕录制」、截图黑屏**：打包脚本此前从未对 LaterScreen.app 做 codesign，产物是「未密封 bundle + 仅二进制 linker-signed」。macOS 15+ 的屏幕录制 TCC 校验走 bundle 语义，进程身份校验必败——授权记录钉住的代码要求与运行进程永远对不上，表现为每次采集都弹授权、采集被拒返回黑帧。现打包时先签内部二进制、再密封整个 bundle（Info.plist 与资源入签名），身份校验恢复通过。

## 🔐 签名与授权（重要变化）

- 产物改用**自签名代码签名证书**密封签名（证书随签名内嵌分发，无需 Apple 开发者账号，未做公证）。TCC 授权绑定证书身份：**之后所有版本的升级都不再要求重新授权**（此前 ad-hoc 以 cdhash 锚定，每次升级二进制变化都要重来）。
- 首次安装仍需授权一次「屏幕录制」（系统弹窗允许即可）；裸 F 键热键仍需在 系统设置 ▸ 隐私与安全性 ▸ 辅助功能 添加 LaterScreen。
- macOS 15+ 会对所有截屏应用做周期性「继续允许」确认提醒，属系统行为、与应用签名无关，点一次即可。
- 从 v0.14.3 及更早（ad-hoc 时代）升级到本版：签名身份变更，**屏幕录制与辅助功能需要重新授权最后一次**；之后长期稳定。

## ✅ 真机验证（M6 / macOS 27）

崩溃修复后 GUI 子进程存活、截屏 2560×1440 真实像素、OCR（Vision）精确识别、二维码路径正常、`cargo test --workspace` 全绿；未密封 → 密封签名后，TCC 条目 csreq 与运行进程 `codesign -v -R` 校验一致，截图黑屏与反复弹窗消失。
